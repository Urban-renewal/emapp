# Track B heartbeat — 2026-05-30

- **PERF-2 (getMe SSR self-hop) — DEFERRED to infra/deploy layer (with T6),
  per owner decision (option D).** Track B does NOT build it.
  - Root cause (analysis preserved for the infra owner): `getMe` /
    `getProviderMe` run server-side and fetch `${origin}/api/v1/me` — the
    Next app's OWN proxy route (`app/api/[...path]/route.ts`) — which then
    forwards to `API_BACKEND_URL`. Under the dev server's limited worker
    pool an SSR request waiting on another route of the same server can
    deadlock; in all envs it's a double-hop on every authenticated page.
  - Why it left Track B's FE-fix surface: no NEW BE endpoint is needed, but
    the clean root fix (have RSC/server code call `API_BACKEND_URL` directly,
    bypassing the proxy self-hop) is a change to a deliberately-centralized
    boundary — `selfOrigin()` (§v9-H-1 Host allowlist) + the "one place where
    the backend hostname lives" proxy design — and its prod behavior
    (Cloudflare Pages RSC → private Railway URL) can only be validated at the
    infra/deploy layer. The alternatives each carry a tradeoff a pure FE slice
    shouldn't decide: a short-TTL session cache widens the token-revocation
    window (intersects open redteam-H-1); timeout-only is symptom-not-root
    (D.51). Hence deferral to infra/deploy alongside T6.
