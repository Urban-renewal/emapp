קובץ 2 — פרוטוקול ה-Autopilot (נכנס ל-CLAUDE.md)

הוסף את הבלוק הזה ל-CLAUDE.md (אחרי החלק הקיים). זה מה שגורם להתנהגות האוטומטית:

## ===== AUTOPILOT PROTOCOL =====

### On every session start
1. Read PROGRESS.md → identify Current Position + Next task.
2. Read GATES.md → know if the next task is a critical gate.
3. State to the user: "אני ב-Phase X, משימה הבאה PX.Y. ממשיך."
   Then proceed WITHOUT waiting (unless it's a gate — see below).

### The task loop (repeat automatically per task)
For the Next task (e.g., P0.4):
1. Read the task from its source doc:
   - Phase 0 → docs/04b-phase-0-foundation.html, find PX.Y
   - Phase 1 → docs/04c-phase-1-database.html, find PX.Y
   - Phase 2+ → docs/03-mvp-roadmap.html, the matching phase section
2. Extract: goal, files, dependencies, required tests (TX.Y),
   Definition of Done.
3. Verify dependencies are done (check PROGRESS.md). If a dependency
   is missing → STOP, write Blocked in PROGRESS.md, tell the user.
4. Implement the task.
5. Run the task's tests: pnpm test (+ the specific TX.Y).
   - Fail → fix → re-run. Loop until green. Max 5 attempts, then
     STOP, mark Blocked, explain.
6. Run: pnpm lint && pnpm typecheck. Must pass.
7. Commit (semantic message): git add . && git commit
8. Push: git push
9. Update PROGRESS.md: Next task, Task Log line, checkbox.
10. Move to the next task automatically. Do NOT ask permission
    between tasks within a phase.

### When to STOP and wait for the user (the ONLY stop conditions)
- **End of a Phase:** all tasks in the phase done →
  a) ensure all phase tests green + Definition of Done met
  b) open a PR (see PR protocol below)
  c) update PROGRESS.md (phase checkbox ✓, status: awaiting_approval)
  d) tell the user: "Phase X הושלם. PR פתוח: <url>. ממתין לאישור."
  e) STOP. Do not start the next phase until the user says continue.
- **A critical gate (GATES.md):** stop even mid-phase, per GATES.md.
- **Blocked:** dependency missing, test fails 5x, doc unclear,
  or a decision is needed that isn't in DECISIONS.md → STOP,
  write Blocked + question in PROGRESS.md, ask the user.
- **Security-sensitive task** (any task touching PII/auth/RLS):
  after implementing, BEFORE commit, run
  "@security-reviewer review the diff". Fix CRITICAL before commit.
  (This does not stop for the user — it's an internal gate.)

### PR protocol (end of each phase)
1. Create a branch at phase start: git checkout -b phase-X
   (all phase commits go here)
2. At phase end: git push -u origin phase-X
3. Open PR via gh CLI:
   gh pr create --title "Phase X — <name>" --body "<summary>"
   Body must list: tasks completed, tests passing, Definition of
   Done checklist, anything the reviewer should focus on.
4. Tell the user the PR URL. STOP.
5. User merges = approval. User comments = fix and update the PR.
6. After merge: git checkout main && git pull, then next phase
   starts on a new branch.

### Never
- Never skip a test to "make progress".
- Never start the next phase before PR merge.
- Never proceed past a Blocked state silently.
- Never modify GATES.md or this protocol without the user.

קובץ 4 — GATES.md (נקודות עצירה קריטיות)

מעבר לסוף-Phase, יש רגעים שבהם Claude עוצר גם באמצע Phase. שמור ב-~/emapp/GATES.md:

# EMAPP — Critical Gates (Claude stops here even mid-phase)

These are points where a mistake is expensive/irreversible.
Claude MUST stop, present what it's about to do, and wait for "כן".

## Gate 1 — Before the first migration touches production schema
Task: P1.1 (first Drizzle migration)
Why: schema mistakes compound. Review the migration plan before run.
Stop and show: the full migration SQL + the rollback plan.

## Gate 2 — Before enabling RLS FORCE on tables
Task: P1.11 (RLS policies)
Why: get this wrong = cross-tenant leak OR app locked out of its own DB.
Stop and show: every RLS policy + the T1.5 isolation test result.

## Gate 3 — Before PII encryption goes live
Task: P1.5 (owners + pgcrypto)
Why: wrong key handling = unrecoverable PII or a leak.
Stop and show: key sourcing (env, never hardcoded) + round-trip test.

## Gate 4 — Before Tenant SMS auth goes live
Task: Phase 2 (Tenant SMS OTP)
Why: SMS costs real money + OTP bugs = anyone logs in as any tenant.
Stop and show: rate-limit config + OTP expiry + the Israeli SMS
provider config (no secrets in code).

## Gate 5 — Before first production deploy
Task: Phase 9 (Launch)
Why: it's production. Real customer data.
Stop and show: the full pre-launch checklist (Doc 07 §15).

## Gate 6 — Any time DECISIONS.md would need a new entry
Why: an architectural decision is being made. You must decide it,
not Claude.
Stop and show: the decision, options, Claude's recommendation.

למה זה עובד (ולמה לא ייתקע)

  • PROGRESS.md = זיכרון בין sessions. גם אם תסגור הכל ל-3 ימים, session חדש קורא אותו ויודע בדיוק איפה לחזור.
  • ה-Docs = מקור המשימות. כל P*.X כבר כתוב עם tests + DoD. Claude לא ממציא — הוא מבצע.
  • GATES.md = בלם. הדברים היקרים (migrations, RLS, PII, SMS, production) — אתה מאשר אותם ידנית. השאר זורם.
  • PR = שער האישור. merge = "אני מאשר את כל ה-Phase". לא צריך לאשר 14 משימות בנפרד.
  • Blocked state = רשת ביטחון. Claude לא "ממשיך בכל מחיר" — אם משהו לא ברור, הוא עוצר ושואל, לא מנחש.

זה ההבדל בין "כלי שאני צריך לנהל ידנית כל הזמן" לבין "צוות שעובד לבד ומדווח לי בנקודות הנכונות".
