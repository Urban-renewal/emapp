> סטטוס: **DESIGN — עוצב יחד עם הבעלים, 2026-06-10. מקור-אמת לפני בנייה. שום דבר לא נבנה.**

> נכתב בעברית בכוונה (קהל-הסקירה הראשי הוא הבעלים); שמות-טבלאות/שדות ב-`code` כדי שלא יישברו בקריאה.

## 1. המציאות הדומיינית (הראש של ארגון התחדשות-עירונית)

המארגן (יזם / עו"ד / מנהל-מתחם) לא מקליד בניינים. המטרה היחידה שלו: **להגיע לסף-ההסכמה החוקי** (תמ"א 38 / פינוי-בינוי) **מהר, עם שובל-ראיות נקי**. הכאב: לרדוף אחרי בעלים שהוא מכיר לעיתים רק מנסח-טאבו (שם + חלק, בלי קשר).

שתי אמיתות שמעצבות את כל המודל:

- **בעל-זכויות (טאבו) = היחיד שחותם ונספר לסף.** השוכר אינו יישות-חתימה ואינו בספירה — הוא רק **מקור-מידע בשלב-הגילוי** (ניגשים אליו פיזית כדי לברר מי הבעלים).
- **המערכת מקימה את הפרויקט, לא המשתמש.** כל פעולה-ידנית היא כשל-תכנון. הייבוא / ההקמה-מ-גוש-חלקה הם ה-onboarding הראשי; הזנה-ידנית = תיקון-חריג בלבד.

## 2. מודל-הישויות

```
פרויקט → בניין → דירה → ownership(חלק) → בעלים  (שלד-able · ריבוי-בעלים)
דירה   ← רשומת-גילוי [סטטוס · טקסט-חופשי · (נדחה) אודיו+תמלול]
בעלים  ← אנשי-קשר (טלפון/מייל · מתרבים בהדרגה)
חתימה  = (מסמך × נמען) ;  נמען ∈ { בעלים , קבלן }
```

עקרונות:

- **דירה ↔ בעלים = רבים-לרבים** דרך `ownerships`, כל שורה נושאת **חלק** (share).
- **שוכר/דייר אינו `owner`** — הוא מקור-גילוי המקושר לדירה. לעולם לא חותם, לעולם לא בסף.
- **בעל-זכויות בלבד** הוא נמען-חתימה ונספר לסף.

### מה כבר קיים בקוד (בונים על זה, לא מאפס)

- `ownerships` עם trigger שאוכף סכום-חלקים = 100 לדירה (מיגרציה 0030) — **ריבוי-בעלים + חלקים כבר נתמך חלקית.**
- `owners` עם PII מוצפן (pgcrypto), `national_id` / `phone` כשדות-רגישים.
- שירות-חתימות קיים (`signature-requests.service.ts`) — כולל `resolveRenterOnly` שמתייחס לשוכר כסוג-של-בעלים. **זה בדיוק הבלבול שיפורק** (שוכר → מקור-גילוי, לא owner).

## 3. בעלים-שלד + העשרה הדרגתית

- ביצירה: `name` / `national_id` / `phone` **כולם אופציונליים**. אפשר ליצור בעלים עם שם-בלבד, או אפילו רק חלק-בדירה ללא שם.
- כל ישות נושאת **מצב-השלמה**: `skeleton → partial → ready_to_sign`.
- **שליחת-חתימה חסומה** עד שיש זהות + איש-קשר (אחרת אין למי לשלוח ואין מה לאמת).
- ה-UX מציג את **"הפאזל"**: כמה מהבניין מופה, כמה בעלים אותרו, כמה מוכנים-לחתימה. אנשי-השטח משלימים בהדרגה — זו המהות.

## 4. הקמה-אוטומטית (כוכב-הצפון)

מפרידים **שתי שכבות** כי הן שונות מהותית בחוק ובמורכבות:

### 4א. שלד פיזי/תכנוני — קל, רשמי, ללא PII ✅

מ-**גוש-חלקה** אוספים אוטומטית מבנים/קומות/יחידות/גיאומטריה ממקורות רשמיים:

- **GovMap** (מפ"י / רמ"י) — שכבות גוש/חלקה + טביעת-מבנים.
- **מנהל-התכנון / mavat** — תב"ע + זכויות-בנייה (רלוונטי ישירות לתמ"א/פינוי-בינוי).
- **data.gov.il** — דאטה-סטים פתוחים.
  → זו ההקמה-האוטומטית של השלד, חוקית ובלי מידע-רגיש.
  > ⚠️ זמינות-ה-API המדויקת + ה-ToS של GovMap/mavat **חייבים אימות** לפני הסתמכות. הנוף מתואר נכון; endpoint ספציפי לא אושר.

### 4ב. בעלות — ערך-גבוה, אבל קשה משפטית+טכנית

- **נסח-טאבו** הוא מקור-הזהב לבעלות+חלקים, אבל **אין API חופשי לשליפה-בכמות**; גישה בתשלום פר-נסח, ושליפה-אוטומטית מוגבלת ב-ToS + **חוק הגנת הפרטיות**.
- הריאלי: **"העלה נסח → אנחנו מפענחים"** (parse), או אינטגרציה-בתשלום — **לא** scrape.

**מסקנה:** שלב-1 של האוטומציה = שלד-פיזי מ-גוש-חלקה. בעלות = פיענוח-נסח-בהעלאה. ~80% מהערך בלי הסיכון המשפטי.

## 5. חתימות

- **בקשה = (מסמך × נמען).** סקייל = לולאה על נמענים, לא שינוי-במסמך.
- **מטריצת-שיוך (התיקון ל-#2):**

| נמען  | היקף-מסמך     | כלל                                               |
| ----- | ------------- | ------------------------------------------------- |
| בעלים | מסמך-**דירה** | חייב להיות `ownership` של אותה דירה               |
| בעלים | מסמך-פרויקט   | חייב `ownership` כלשהו בפרויקט                    |
| קבלן  | מסמך-קבלן     | הקבלן חייב להיות **משוייך לפרויקט** (ה-share שלו) |

- **ריבוי-בעלים:** מסמך-דירה → **נשלח לכל הבעלים** של אותה דירה. זה השימוש הראשון של ה-fan-out.
- **סקייל ("לחיצה אחת → כמה נמענים"):** fan-out של בקשות על **אותו מסמך** (לא mail-merge). נדחה לבנייה, אבל המודל `(מסמך × נמען)` כבר תומך — אפס חוב עתידי.
- **ספירת-סף:** יחידת-הספירה ברמת-**הדירה** (לא חלק-משוקלל פר-בעלים-בודד); המערכת **משקפת תמונת-מצב** (כמה מהבעלים-המשותפים חתמו לכל דירה).
  > ⚠️ **הכלל-המשפטי המדויק לספירה (לפי חלקים/דירות/ראשים) — דורש יועץ-משפטי.** זו הליבה המתדיינת; לא נקבע פה.

### באגים מהביקורת שנסגרים פה (מאומתים בקוד)

- **#2 — אין בדיקת-שיוך** ב-`signature-requests.service.ts`: בודק גלוּת-מסמך + בעלים-קיים, **לא** ש-`ownership` קושר את הבעלים לפרויקט/דירה. מטריצת-השיוך למעלה היא התיקון.
- **#3 — guard ה-dedup מתעלם מתפוגה:** הבדיקה `status='pending'` בלבד, בלי `expiresAt > now()` → בקשה פגת-תוקף חוסמת חדשה (גם ב-bulk). זה גם מה שגרם ל"לא ראיתי איך לחתום" (#5): קישור-פג הציג מסך-תפוגה במקום את ה-canvas.

## 6. רשומות-גילוי (שכבת-השטח)

- **עכשיו:** `status` (enum גנרי: `not_visited` / `no_answer` / `spoke_to_occupant` / `owner_identified` / `refused` …) + `notes` חופשי.
- **נדחה:** אודיו + תמלול. לבעלים מערכת-תמלול משלו; ההקלטה תיפתח מהאפליקציה בהמשך. **המודל משאיר slot** (`recording_ref` + `transcript`), לא נבנה עכשיו.
- ⚠️ **דגלים-משפטיים לכשייבנה האודיו:** חוקיות-הקלטה (המקליט חייב להיות צד-לשיחה); אודיו = מידע-רגיש (הצפנה/שמירה/DSAR — אותו משטר-PII); אם תמלול חיצוני — נקודת-עיבוד נוספת.

## 7. סדר-פעולה מוצע (phasing)

- **Phase 1 — מודל-ישויות + 2 הבאגים:** שוכר→מקור-גילוי; בעלים-שלד; חשיפת `ownership`-share + שיוך-בעלים-לפרויקט ב-UI; תיקון #2 (מטריצת-שיוך) + #3 (guard-תפוגה).
- **Phase 2 — ייבוא-כ-onboarding:** תצוגה-מקדימה עם **סיכום-שינויים אמיתי** ("X בעלים חדשים, Y דירות, Z מקושרים") במקום "0 שינויים". (בעיה #6.)
- **Phase 3 — הקמה-מ-גוש-חלקה:** שלד-פיזי מ-GovMap/mavat + פיענוח-נסח-בהעלאה.
- **Phase 4 — קמפיין-חתימה:** fan-out בלחיצה-אחת + לוח-מחוונים של הסף (תמונת-מצב).
- **Phase 5+ — שכבת-שטח:** אודיו+תמלול; OSINT (מאחורי בסיס-חוקי, מגודר).

## 11. אמנת-ההרצה (הצינור לכל slice)

`spec(אני) → שחזור-באג(מאמת) → בנייה(בנאי) → טסט-עצמאי(≠בנאי) → code-review → security-review → QA-דפדפן(happy+שגיאות+זמן+אבטחה) → מיזוג-בשער-ירוק → critic-שלמות → זיכרון`

- בנאי לעולם לא מכריז "סיימתי"; השלבים-העצמאיים מאמתים.
- **שער-מיזוג ירוק** = טסטים + code-review PASS + security ללא-CRITICAL + CI ירוק + QA-דפדפן. אחרת ה-slice נשאר פתוח עם חוסם-ברור. לעולם לא force-merge.
- שחזור-קודם-תיקון (להוכיח שהבאג קיים→שנעלם). שער-שורש D.51. regression+flakes(rerun). ledger-ראיות. עוגני-הקשר (מסמך+זיכרון) בתחילת כל slice. בלי המתנה-אינסופית.

## 12. Phase 0 — בסיס-ביצועים (נמדד 2026-06-10)

| נתיב                             | זמן                                                  |
| -------------------------------- | ---------------------------------------------------- |
| דפדפן→proxy→API→Neon, **חם**     | **~200ms** ✅                                        |
| route בפעם-ראשונה (קר)           | שניות — **קומפילציית-Next-on-demand (dev בלבד)**     |
| DB round-trip (Neon, `SELECT 1`) | ~155ms                                               |
| `/health` עיבוד (בלי DB)         | ~5ms                                                 |
| curl connect ל-localhost         | ~205ms — **fallback IPv6→IPv4 של Windows, dev בלבד** |

**מסקנה:** ה->1s = קומפילציית-dev (חם=200ms מוכיח). **תיקון להשערה מוקדמת:** ה-DB אינו שנייה — 155ms.
**מנוף-פרוד יחיד (לא cache):** ה-155ms של Neon → pooled-endpoint + co-location region + צמצום round-trips.
⚠️ **לא ניתן לאשר פרוד-<1s ממדידת-dev** (stack שונה: Pages-Function+Railway). **שער-חובה: מדידה ב-staging לפני-פרוד.**
