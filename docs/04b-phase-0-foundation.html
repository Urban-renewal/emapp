01 · Phase Overview

What Phase 0 Is, and What It Is Not

Phase 0 is unglamorous infrastructure work. It is also the most important phase to do well, because everything else builds on it.

Phase 0 establishes the shape of the project: how files are organized, how code is shared between frontend and backend, how dependencies flow, how tests run, and how CI verifies everything works. None of this is user-visible. All of it is foundational.

1.1 Phase 0 Goals

By the end of Phase 0, all of these must be true:

  • A new developer can clone the repo and run pnpm dev in under 15 minutes
  • The API responds with 200 OK on GET /health
  • The web app shows a blank RTL page with the Heebo font loaded
  • CI runs typecheck, lint, and tests on every push and PR
  • All Free Tier cloud accounts are created and credentials configured
  • The 8 portability rules are followed from day one (no shortcuts)
  • Conventional commits are enforced via commitlint + Husky
  • Tagged as v0.0.1-phase0 in git

1.2 What Phase 0 Does NOT Include

Easy to scope-creep. Hold the line:

  • Database schema — that is Phase 1
  • Any business logic, entities, or services — Phase 1+
  • Authentication — Phase 2
  • UI components beyond a blank page — Phase 8
  • Production deployment — Phase 9
  • Real users, real data, or real customers

1.3 Why Phase 0 Matters More Than It Looks

Skipping Phase 0 or rushing through it creates a specific kind of pain: you start writing features, then realize a fundamental tooling decision was wrong, and you waste a day untangling. Examples:

  • Wrong monorepo structure — discovered when adding the second package and realizing imports don't work cleanly. Cost: half a day to refactor.
  • Missing T3-env validation — discovered in Phase 4 when an env var was undefined in production. Cost: a 2 AM incident.
  • No CI from day one — first 50 commits are unverified. Discovering broken tests in commit #51 means hours of bisecting.
  • Skipping conventional commits — at month 3, generating a CHANGELOG requires manual archaeology of git log.

The cost of doing Phase 0 right: 2-3 days. The cost of doing it wrong: ongoing friction for the entire project lifetime.

⚠️ The most common Phase 0 mistake
Treating Phase 0 as "just setup" and rushing through it. The setup IS the product foundation. Every minute spent thinking about structure now saves an hour later.

🎯 Decision Point — Israeli ID Implementation

Question: Use a library or implement the Luhn validator ourselves?

Recommendation: Implement. The Israeli ID Luhn algorithm is ~15 lines, well-defined, and validates 9-digit IDs (with padding for shorter ones). No external dependency, full control, easy to test, easy to explain to auditors.

📄 Reference: Israeli ID Validator
packages/validators/src/israeli-id.ts
/**
 * Validates Israeli ID using Luhn algorithm.
 * Israeli IDs are 9 digits. Shorter IDs are padded with leading zeros.
 *
 * @param id - The ID string (digits only, may be 1-9 chars)
 * @returns true if valid, false otherwise
 */
export function isValidIsraeliId(id: string): boolean {
  // Strict input check
  if (typeof id !== 'string') return false;
  if (!/^\d{1,9}$/.test(id)) return false;

  // Pad to 9 digits
  const padded = id.padStart(9, '0');

  // Luhn algorithm
  let sum = 0;
  for (let i = 0; i < 9; i++) {
    let digit = parseInt(padded[i], 10);
    if (i % 2 === 1) {
      digit *= 2;
      if (digit > 9) digit -= 9;
    }
    sum += digit;
  }

  return sum % 10 === 0;
}

🎯 Decision Point — Israeli Phone Implementation

Question: Use libphonenumber-js or implement an IL-only validator?

Recommendation: Implement IL-only. libphonenumber-js is ~130KB minified; we only need Israeli numbers. ~30 lines of code, zero dependencies, and the canonical form is unambiguous. If we ever need other countries (Phase 2 international SMS), we can swap in libphonenumber via ISMSProvider's validation hook.

What we accept (input):

  • 050-1234567 — local format with hyphen
  • 0501234567 — local format without hyphen
  • +972501234567 — E.164 international
  • +972-50-123-4567 — international with hyphens

What we return (normalized output): Always E.164 (+972501234567) or null if invalid. The E.164 format is what we encrypt and HMAC for storage in the owners.phone_encrypted column.

📄 Reference: Israeli Phone Validator
packages/validators/src/israeli-phone.ts
/**
 * Israeli mobile/landline phone validator and normalizer.
 *
 * Israeli phone numbers:
 *   - Country code: +972
 *   - Mobile prefixes: 050, 052, 053, 054, 055, 058 (and historical 057, 059)
 *   - Landline prefixes: 02, 03, 04, 08, 09 (city codes)
 *   - Mobile total: 10 digits (0XX-NNNNNNN) or 13 chars with country (+972XX-NNNNNNN → 12 digits after +)
 *   - Landline total: 9 digits (0X-NNNNNNN)
 *
 * Normalized form: E.164 (+972 prefix, no spaces or hyphens).
 * Example: '050-1234567' → '+972501234567'
 */

// Mobile prefixes (current + historical), without leading 0
const MOBILE_PREFIXES = ['50', '52', '53', '54', '55', '57', '58', '59'];
// Landline area codes (single digit after the leading 0)
const LANDLINE_PREFIXES = ['2', '3', '4', '8', '9'];

export function normalizeIsraeliPhone(input: string): string | null {
  if (typeof input !== 'string') return null;

  // Strip all whitespace, hyphens, parens, dots
  const cleaned = input.replace(/[\s\-().]/g, '');
  if (cleaned.length === 0) return null;

  let digits: string;

  if (cleaned.startsWith('+972')) {
    digits = cleaned.slice(4);
  } else if (cleaned.startsWith('972')) {
    digits = cleaned.slice(3);
  } else if (cleaned.startsWith('0')) {
    digits = cleaned.slice(1);
  } else {
    return null;
  }

  if (!/^\d+$/.test(digits)) return null;

  // Mobile: 9 digits total (2-digit prefix + 7-digit subscriber)
  if (digits.length === 9) {
    const prefix = digits.slice(0, 2);
    if (MOBILE_PREFIXES.includes(prefix)) {
      return `+972${digits}`;
    }
    return null;
  }

  // Landline: 8 digits total (1-digit area + 7-digit subscriber)
  if (digits.length === 8) {
    const prefix = digits.slice(0, 1);
    if (LANDLINE_PREFIXES.includes(prefix)) {
      return `+972${digits}`;
    }
    return null;
  }

  return null;
}

export function isValidIsraeliPhone(input: string): boolean {
  return normalizeIsraeliPhone(input) !== null;
}

    expect(normalizeIsraeliPhone('05012345678')).toBeNull();
  });

  it('rejects non-numeric characters in core digits', () => {
    expect(normalizeIsraeliPhone('050-12X-4567')).toBeNull();
  });

  it('rejects empty string', () => {
    expect(normalizeIsraeliPhone('')).toBeNull();
  });

  it('rejects non-string input', () => {
    expect(normalizeIsraeliPhone(972501234567 as any)).toBeNull();
  });
});

describe('isValidIsraeliPhone', () => {
  it('returns true for valid input', () => {
    expect(isValidIsraeliPhone('050-1234567')).toBe(true);
  });

  it('returns false for invalid input', () => {
    expect(isValidIsraeliPhone('garbage')).toBe(false);
  });
});
💡 Why E.164 as the canonical form
One canonical format means one search key. If we store 050-1234567 in one row and +972501234567 in another, deduplication is impossible and HMAC search misses matches. By normalizing to E.164 at the API boundary, every phone in owners.phone_encrypted is in the same form. The HMAC of that value (owners.phone_hash) becomes a reliable search key. This is the same reason we pad Israeli IDs to 9 digits — one canonical form per value.

import { NestFactory } from '@nestjs/core';
import { FastifyAdapter, NestFastifyApplication } from '@nestjs/platform-fastify';
import helmet from '@fastify/helmet';
import { AppModule } from './app.module';
import { Logger } from 'nestjs-pino';
import { env } from '@app/config';

// CORS origin allow-lists — see CORS_ORIGINS.md for the full rationale.
// Production-only includes the live FE domain. Preview includes all Cloudflare Pages
// preview deployments (regex). Development includes the local dev server.
const CORS_ORIGINS = {
  production: [
    'https://app.emapp.io',
    // Provider Admin tool lives at the same domain under /provider/* (Phase 6.5)
  ],
  preview: [
    /^https:\/\/[\w-]+\.emapp\.pages\.dev$/,  // CF Pages PR previews
  ],
  development: [
    'http://localhost:3001',  // Next.js dev server
    'http://127.0.0.1:3001',
  ],
};

async function bootstrap() {
  const app = await NestFactory.create<NestFastifyApplication>(
    AppModule,
    new FastifyAdapter({ trustProxy: true }),
    { bufferLogs: true },
  );

  app.useLogger(app.get(Logger));

  // API versioning: every endpoint under /api/v1/* — see Doc 06 §5.1
  app.setGlobalPrefix('api/v1');

  await app.register(helmet, {
    contentSecurityPolicy: {
      directives: {
        defaultSrc: ["'self'"],
        scriptSrc: ["'self'"],
        styleSrc: ["'self'", "'unsafe-inline'"],  // shadcn/Tailwind needs inline styles
        imgSrc: ["'self'", 'https://*.r2.cloudflarestorage.com', 'data:'],
        connectSrc: ["'self'", 'https://*.sentry.io', 'https://api.resend.com'],
        fontSrc: ["'self'", 'https://fonts.gstatic.com'],
        objectSrc: ["'none'"],
        baseUri: ["'self'"],
        formAction: ["'self'"],
        frameAncestors: ["'none'"],
      },
    },
    hsts: {
      maxAge: 31536000,        // 1 year
      includeSubDomains: true,
      preload: true,           // eligible for browser preload lists
    },
    crossOriginEmbedderPolicy: false,  // not needed for our SPA pattern
  });

  // CORS — production = strict, preview = regex match, dev = localhost
  const allowedOrigins = [
    ...CORS_ORIGINS[env.NODE_ENV] ?? [],
    ...(env.NODE_ENV === 'production' ? CORS_ORIGINS.preview : []),
  ];

  app.enableCors({
    origin: (origin, callback) => {
      // no origin = same-origin or curl/server-to-server, allow
      if (!origin) return callback(null, true);
      const allowed = allowedOrigins.some((entry) =>
        entry instanceof RegExp ? entry.test(origin) : entry === origin,
      );
      callback(allowed ? null : new Error(`CORS: origin ${origin} not allowed`), allowed);
    },
    credentials: true,           // allow cookies (refresh token)
    methods: ['GET', 'POST', 'PATCH', 'DELETE', 'OPTIONS'],
    allowedHeaders: ['Authorization', 'Content-Type', 'X-Reason'],  // X-Reason for Provider audit
    maxAge: 86400,               // 24h preflight cache
  });

  app.enableShutdownHooks();

  const port = parseInt(env.PORT_API ?? '3000', 10);
  await app.listen(port, '0.0.0.0');
}

bootstrap().catch((err) => {
  console.error('Failed to start API:', err);
  process.exit(1);
});

import { Controller, Get } from '@nestjs/common';
import { sql } from 'drizzle-orm';
import { db } from '@app/db';

@Controller('health')
export class HealthController {
  @Get()
  async getHealth() {
    let dbStatus = 'unknown';
    try {
      await db.execute(sql`SELECT 1`);
      dbStatus = 'connected';
    } catch {
      dbStatus = 'disconnected';
    }

    return {
      status: dbStatus === 'connected' ? 'ok' : 'degraded',
      db: dbStatus,
      uptime: Math.floor(process.uptime()),
      timestamp: new Date().toISOString(),
    };
  }
}

? · Troubleshooting

Common Phase 0 Problems

Issues that bite developers during Phase 0 setup. Solutions tested.

Problem: pnpm install hangs or fails

Symptom: Long install times, or "ERR_PNPM_PEER_DEP_ISSUES" errors.

Solutions:

  • Run pnpm store prune to clean stale cache
  • Add auto-install-peers=true to .npmrc
  • Verify packageManager field in root package.json matches your installed version
  • Try pnpm install --force to rebuild lockfile

Problem: Turborepo "no tasks were executed"

Symptom: turbo dev says no tasks found.

Solution: Check that each package's package.json has the script defined. Turbo only finds tasks declared in workspace packages. The root turbo.json just configures the pipeline.

Problem: NestJS won't start with Fastify

Symptom: Errors about Express types or middleware compatibility.

Solution: Make sure you removed @nestjs/platform-express from dependencies. Use @fastify/helmet not helmet. Some Express middlewares don't work with Fastify — check the NestJS docs for Fastify-specific alternatives.

Problem: Next.js RTL doesn't apply

Symptom: Page renders LTR despite dir="rtl".

Solution: Make sure dir="rtl" is on the <html> element, not just <body>. Verify with DevTools. Tailwind RTL plugin requires explicit usage of rtl: prefixes — for general RTL, the HTML attribute is enough.

Problem: T3-env throws on startup

Symptom: "Invalid environment variables" error before app starts.

Solution: The error message lists which vars failed validation. Check .env.local exists in the package that runs (not just root). Ensure variables are actually loaded — Next.js loads .env.local automatically; NestJS may need @nestjs/config or dotenv at startup.

Problem: Husky hooks don't run

Symptom: Bad commit messages get through; lint-staged doesn't trigger.

Solutions:

  • Run pnpm exec husky init to set up the .husky folder
  • Verify hooks are executable: chmod +x .husky/*
  • Check .git/config has hooksPath = .husky
  • Re-run pnpm install — Husky's prepare script should re-link hooks

Problem: Sentry doesn't receive events

Symptom: Threw an error, nothing in Sentry dashboard.

Solutions:

  • Verify DSN is correct (copy-paste from Sentry project settings)
  • Check NODE_ENV isn't causing Sentry to skip events (some configs disable in dev)
  • Wait 1-2 minutes — Sentry has ingestion delay
  • Check Sentry project quotas — if exceeded, events are dropped silently

Problem: Docker build fails on monorepo

Symptom: "Cannot find package @app/db" during build.

Solution: The Dockerfile must copy the workspace structure correctly. Use the multi-stage pattern from P0.9 reference. Common mistake: copying only apps/api without packages/. The whole workspace needs to be available during install.

Problem: CI is slow (> 5 minutes)

Symptom: CI takes 5+ minutes when it should take 2-3.

Solutions:

  • Add Turborepo remote caching (TURBO_TOKEN secret) — biggest speedup
  • Verify pnpm cache is hitting — check the GitHub Actions log
  • Run jobs in parallel (typecheck, lint, test all start at the same time)
  • Use --frozen-lockfile in install — slightly faster than default
