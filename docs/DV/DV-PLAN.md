# DV — Deep "as-a-user" Verification (methodology)

> Source of truth for the DV pass. Co-designed with the owner (2026-06-02).
> Mechanically derived from `origin/main @ 9121361`. **This file is the plan;
> `INVENTORY.md` is the closed checklist; `results/<interface>.md` hold the
> per-item detail; `FINDINGS.md` is the triaged rollup.**

## 0. The one principle that kills "lost context"

No agent (and no human) **remembers** — a **file remembers**. Every observation
is written to `docs/DV/` the moment it's made. State lives in checkboxes, not in
an agent's head. If any agent dies / resets, the next reads the files and resumes
at the first empty checkbox. Every hand-off (investigator → fixer → re-verify) is
a **self-contained file entry** (path + repro + artifact + root-cause), so the
receiver needs zero memory of the sender's session.

## 1. Scope

- **Starts from the point AFTER a successful login.** Login / OTP / MFA / signup
  are **OUT of scope** — verified at the infrastructure level already.
- **4 interfaces** (below). Login credentials are **setup only, not under test**:
  they get us to the post-login starting state.
- **In scope:** every page, every non-page surface (nav, modals, org-switcher,
  toasts, search/filter, forms), every entity, the cross-interface lifecycles,
  and the deliberate error-handling / adversarial pass.
- **Out of scope (deferred by decision):** SEC-1..8, MFA-exercise, PERF-1/2
  colocation, subdomain cutover, ISO. (See FINDINGS-REGISTER.)

## 3. The axes every item is scored on

| Axis                             | How                                                                                 | Hat                          |
| -------------------------------- | ----------------------------------------------------------------------------------- | ---------------------------- |
| **works / broken**               | behavioral — does the control do what it should                                     | investigator                 |
| **error-handling** (central)     | behavioral — bad/invalid/out-of-order input → graceful, clear, no crash/corruption  | adversarial                  |
| **ergonomics / missing-feature** | behavioral — friction, clicks, absent-but-expected (improve within existing design) | investigator                 |
| **runtime**                      | behavioral timing (network panel) + static N+1/EXPLAIN                              | investigator + code-reviewer |
| **SOLID**                        | static — layering, single-responsibility, no ad-hoc pattern                         | code-reviewer                |
| **security**                     | static — PII / IDOR / auth / injection                                              | security-reviewer            |

**Oracle (so "works ✓" ≠ "rendered something"):** the seed is known
(`seed:demo`, validated by `verify-seed.ts`). We derive an **expected-state
reference** and assert **actual == expected** (the right %, the agent sees
_exactly_ the assigned projects and no others, masked PII shows `•••`).

## 4. Agent roster — separated hats (each its own clean context)

| Hat                                     | Read/Write                        | Job                                                                                               | Boundary                                               |
| --------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **Coverage investigator**               | read-only code; writes `docs/DV/` | drive live app per-role, every surface, capture artifacts, assert vs oracle                       | **never edits code** (enforced: no Edit/Write to code) |
| **Adversarial investigator** (separate) | read-only code; writes `docs/DV/` | deliberately break it — invalid/boundary/malformed/out-of-order input; **focus = error handling** | read-only; mutates only LOCAL data (reseeded)          |
| **code-reviewer** (static)              | read-only                         | SOLID · N+1/runtime · plaster (D.51)                                                              | judges, doesn't fix                                    |
| **security-reviewer** (static)          | read-only                         | PII · IDOR · auth · injection                                                                     | judges, doesn't fix                                    |
| **Triage**                              | —                                 | owner + orchestrator classify + prioritize the full findings                                      | the one human checkpoint                               |
| **Fixer** (separate)                    | edits code                        | one finding → one slice → root-cause → reviewers + CI → PR                                        | never grades itself; Gate-6 stops for owner            |
| **Re-verify**                           | the investigator re-drives        | red→green behavioral confirmation of the fixed flow                                               | the fixer's fix is not "done" until this passes        |

## 5. Run model — autopilot where it's safe

- **Discovery (coverage + adversarial) = autopilot to the end.** It is
  **read-only on main**, so the worst case is an imperfect findings file, never a
  broken system. No mid-run approvals.
- **File-based incremental logging** — committed **after every item** (a crash
  loses one item, not the run). Owner can **peek the live file anytime** without
  stopping the agent.
- **Self-gate on item #1** — the investigator validates its first artifact
  against the §6 standard before continuing; the owner peeks after interface #1
  and course-corrects the _running_ agent by message (not restart).
- **One checkpoint: Triage** — after the _full_ discovery lands, owner picks the
  fix-list. Not a restart-stop; a single deliberate decision (decide-after-seeing-all).
- **Fixing = autopilot per-slice**, but every PR through reviewers + CI; **Gate-6
  (policy / migration / breaking shared-types) STOPS for owner**.
- **Sequential, never parallel** (owner preference) — one investigator, then the
  adversarial pass, then fixes one slice at a time.

## 6. Artifact standard (what "covered" means)

A surface is **covered only when it has an artifact bundle**, never "✓":

1. **Screenshot** of the rendered state.
2. **Network** capture for any action (method, URL, status, payload shape, timing).
3. **Console** log (zero unexpected errors, or the error captured).
4. **Server log** line for the triggered request (and the audit row if sensitive).
5. **Assertion vs oracle** (actual == expected value, not "looks populated").

No artifact → checkbox stays empty → **visibly** uncovered.

## 7. Completeness — mechanical, not vigilance

1. **INVENTORY from 3 independent extractions:** route-tree (pages) ·
   **component-tree** (buttons / forms / modals / nav) · endpoint list
   (controllers). If it exists in code, ≥1 extraction catches it.
2. **Reconciliation** (orchestrator, mechanical): every API endpoint hit by ≥1
   UI action OR marked "not user-reachable"; every FE route visited.
3. **Completeness-critic** at the end: "which items have no artifact? which
   code-paths have no inventory row?" → next round.
4. **Honest residual:** state-conditional UI (a control that appears only in a
   data state). Covered by the §9 state-matrix + the lifecycles; what the matrix
   can't reach is logged explicitly, never disguised as "covered."

## 8. Data protocol

- DV runs against the **isolated LOCAL Postgres** (`start-dev-local.ps1`), never
  shared Neon.
- **Pinned seed: `seed:demo`** (rich — projects across all statuses). The
  expected-state oracle is derived from it.
- **Reseed to the known state before each phase** (coverage → adversarial →
  re-verify) so mutations don't leak between passes.
- **Noop providers only** — email (Resend→Noop, payload to log), SMS (Noop, code
  to log), R2 local. DV never sends a real email / SMS / prod-R2 write.

## 9. Non-page surfaces + state matrix (the things route-lists miss)

**Non-page surfaces (per interface):** sidebar/nav (per-role: manager sees
+members/audit/settings; agent/viewer don't) · org-switcher (Alpha↔Beta =
cross-tenant isolation) · modals/dialogs (confirm-archive/suspend · reveal-PII ·
Access-Reason) · toasts / inline errors · search / filters · pagination · every
`<form>` carries `method="post"` (CLAUDE.md DoD — GET-fallback = credential leak).

**State matrix (per key screen):** empty (no projects/owners/docs) · loading
(skeleton, UX-2) · error (500 / 403 / 404 / network-down) · large list (perf at
volume) · RTL / Hebrew / date in Asia-Jerusalem.

## 10. Cross-interface lifecycle scripts (the synchronization layer)

Each step = a checkpoint with an artifact + oracle assertion.

```
L1 — full signature cycle (the product's heart)
 Manager: create project → building → apartment → owner → ownerships(=100) → send to signature
   [✓ request created, status=pending, audit row]
 → Resident (tenant portal): receive → open → sign
   [✓ signature saved (SVG, sms_otp), audit row]
 → Agent: open the project
   [✓ signature appears, progress % rose by the right amount]
 → Manager: owners + progress
   [✓ full sync; cancelled NOT counted; archived NOT counted (D.57)]
 → Contractor (manager-generated share-link): progress
   [✓ aggregate reflects it; archived excluded; NO owner PII; consent-vs-threshold stat]

L2 — import flow (high-value error-handling)
 Manager: upload CSV → mapping → errors → commit  [✓ partial-failure handling, error page]

L3 — ownerships set-replace (strict invariant D.25)
 Manager: edit ownerships  [✓ sum must equal 100; 90/110/negative/overlap rejected clearly]

L4 — provider cross-tenant (audited)
 Provider: open a tenant → suspend → reactivate  [✓ Access-Reason enforced, audit rows, org goes inert]
```

## 11. Behavioral checks beyond the screen

- **Audit trail:** every sensitive action (reveal-PII · provider access · suspend ·
  share-mint · signature) **writes an audit row** — DV verifies the row, not just
  the UI.
- **Notifications:** a manager action that should notify → the notification
  appears for the right party (cross-interface).
- **Non-UI artifacts:** open exported xlsx/PDF and **look at it** (masked PII,
  no formula injection); read the email/SMS payload from the Noop log.

## 12. Definition of Done (for the DV pass itself)

DV is done when: every INVENTORY item has an artifact + status · every `broken`
is fixed + re-verified **or** explicitly deferred with owner sign-off · every
janky → polish-slice or accepted · every lifecycle green · reconciliation shows
0 unvisited routes / 0 unhit endpoints · FINDINGS triaged. **No silent caps** —
anything sampled/skipped is logged.

## 13. Tooling

Drive the **live browser** (real, owner can watch). Every **confirmed** flow is
then locked as a **Playwright e2e** so it becomes a permanent CI regression gate.
